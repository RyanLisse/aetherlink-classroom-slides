# Teaching structure for every workshop

Each lesson uses the participant's next action to organize the explanation.
Keep one practice system throughout the day. Explain a concept immediately
before the participant uses it.

## A lesson block

1. Explain the problem and the purpose of the next change.
2. Demonstrate one change with its input and visible output.
3. Let each participant repeat the change in their own workspace.
4. Check the result, including a useful failure or refusal case.
5. Discuss why the result happened. Solo participants write the explanation.

An assignment needs a starting state, concrete steps, expected result,
completion evidence, timer, and stop condition. Put lengthy instructions in a
linked participant guide. Screenshots must identify whether they are reference
images, illustrative outputs, or recorded participant runs. An import, dry run
or scripted fallback is not evidence of a model call.

Each day opens with a welcome, a short recap, the scenario and the day plan.
It ends with participant evidence, reflection, and a concrete handoff to the next
day. A handoff names the artifacts to bring and any changed schemas, fixtures,
credentials or environment. Optional work must not become a prerequisite the
next morning.
